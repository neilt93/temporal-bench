\begin{abstract}
Language models at every scale, from 124M parameters to frontier, cannot distinguish fresh context from stale context without explicit elapsed-time annotations --- exhibiting 0\% sensitivity to elapsed time across all ten models tested.
Adding a single natural-language annotation of how long ago information was observed causes temporal sensitivity to emerge (66--100\%) and dramatically reduces false trust in stale information.
This is likely a blind spot in every agent system that serves cached context without age metadata, and the fix is a trivial change at the prompt layer.

We establish this through controlled counterfactual evaluation: each scenario is tested with identical text but different elapsed times, isolating the causal effect of temporal annotation.
Fine-tuned GPT-2 (124M) and TinyLlama (1.1B) jump from 0\% to 66--72\% switch sensitivity when given elapsed-time annotations.
Frontier models show the same pattern: GPT-4o and Claude Opus 4.6 reach 100\% switch sensitivity with explicit time (vs.\ 0--8\% without), while GPT-5.4 reaches 85\%.
A shuffled-time ablation confirms causality --- randomizing elapsed times drops accuracy by 20--30 points, proving models use the temporal signal rather than exploiting surface cues.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Every LLM-based agent today operates over context that was retrieved, cached, or observed at some earlier point in time.
A flight status checked 30 seconds ago is reliable; the same status checked 4 hours ago is not.
Yet language models receive this context as flat text with no indication of age.
The model has no way to know whether it is looking at information from moments ago or from last week.

This paper demonstrates that this is not merely an inconvenience --- it is a \emph{universal failure mode}.
Without elapsed-time annotations, every model we test, from 124M-parameter GPT-2 to GPT-5.4, produces identical actions for fresh and stale context.
They exhibit 0\% switch sensitivity: given the same fact observed 30 seconds ago versus 4 hours ago, they always give the same answer.

The fix is simple.
Adding a single line --- ``Time since this information was observed: 4 hours ago'' --- causes models to differentiate fresh from stale context.
Fine-tuned models jump from 0\% to 66--72\% switch sensitivity.
Frontier models jump from 0\% to 31--100\%.
False trust in stale information drops to near zero for the most capable models.

We call this the \emph{temporal blind spot}: the inability of language models to assess context reliability based on age, despite the fact that temporal reasoning capabilities exist latently in these models and activate immediately when elapsed time is made explicit.

\paragraph{Contributions.}
\begin{enumerate}
    \item We design a \textbf{counterfactual evaluation framework} that isolates the causal effect of elapsed-time annotations on stale-context detection, controlling for all other variables.
    \item We demonstrate the temporal blind spot across \textbf{ten models spanning three orders of magnitude} (124M to frontier), showing it is universal and not a function of model scale.
    \item We show that a \textbf{single natural-language time annotation} eliminates the blind spot, with a shuffled-time ablation confirming causality.
    \item We identify a \textbf{staleness-caution tradeoff}: smaller models over-correct by refreshing stable facts, suggesting that time awareness requires calibration against fact volatility.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\paragraph{Temporal reasoning in LLMs.}
Prior work studies temporal reasoning as a \emph{knowledge} task --- ordering events, resolving temporal expressions, or answering ``when'' questions \citep{ning2018multi,zhou2019going}.
Our focus is fundamentally different: we study temporal reasoning as a \emph{decision-making} task, where the model must decide whether to trust, refresh, or abstain based on how long ago information was observed.
To our knowledge, no prior work has evaluated whether language models can use elapsed time to assess context reliability.

\paragraph{Retrieval-augmented generation.}
RAG systems \citep{lewis2020retrieval} and tool-using agents \citep{schick2023toolformer} retrieve context but do not annotate it with age.
Our results demonstrate that this omission has measurable consequences: without age metadata, models cannot distinguish a passage retrieved moments ago from one cached for days.

\paragraph{Calibration and selective prediction.}
Work on selective prediction \citep{kamath2020selective} and calibrated uncertainty \citep{kadavath2022language} studies when models should abstain.
We add a temporal dimension: models should abstain or refresh specifically when context is \emph{old enough to be unreliable}, and the threshold depends on fact volatility.

\section{Evaluation Framework}
\label{sec:framework}

\subsection{Counterfactual Design}

Our evaluation is built on \emph{counterfactual pairing}: each scenario appears with multiple elapsed times while all other variables are held constant.
Within a counterfactual group, the conversation text, query, available tools (memory, refresh), and deadline constraints are identical --- only the elapsed time changes.
This design isolates the causal effect of temporal information on model decisions.

\subsection{Action Space}

Models choose from five actions:
\begin{itemize}
    \item \textbf{Answer directly}: Trust the cached context and respond.
    \item \textbf{Refresh}: Look up the information again before responding.
    \item \textbf{Retrieve memory}: Check stored memory for a more recent observation.
    \item \textbf{Ask clarify}: Request clarification from the user.
    \item \textbf{Abstain}: Decline to answer due to insufficient confidence.
\end{itemize}

The correct action depends on the interaction between elapsed time and \emph{fact volatility} --- how quickly a given type of information changes.
A stock price is stale after 5 minutes; a home address is reliable for months.
An oracle function encodes this mapping deterministically.

\subsection{Primary Metric: Switch Sensitivity}

Our primary metric is \textbf{switch sensitivity}: the fraction of counterfactual pairs where the model changes its action when the oracle action changes.
Formally, for pairs $(x_i, x_j)$ sharing the same text but different elapsed times:
\[
\text{Switch Sensitivity} = \frac{|\{(i,j) : \hat{y}_i \neq \hat{y}_j \text{ and } y_i^* \neq y_j^*\}|}{|\{(i,j) : y_i^* \neq y_j^*\}|}
\]
where $\hat{y}$ is the model's prediction and $y^*$ is the oracle action.

A model with 0\% switch sensitivity produces the same action regardless of elapsed time.
A model with 100\% switch sensitivity always changes its action when the temporal context warrants it.

\subsection{Synthetic Dataset}

We generate a dataset of 6{,}600 temporal action-selection scenarios spanning 16 fact types across four volatility levels (high, medium, low, stable).
Each example consists of a conversation context, a follow-up query, an elapsed time drawn from 18 log-scaled buckets (5 seconds to 1 year), and a deterministic oracle action.

Counterfactual groups of 6 examples share identical text, tool availability, and deadline constraints --- only elapsed time varies.
The dataset is split at the group level (70/15/15 train/val/test) to prevent data leakage.

\section{Experiment 1: Fine-Tuning}
\label{sec:finetune}

\subsection{Setup}

We fine-tune two models on the synthetic dataset:
\begin{itemize}
    \item \textbf{GPT-2} (124M parameters): Full fine-tuning, learning rate $5 \times 10^{-4}$, 15 epochs.
    \item \textbf{TinyLlama-1.1B}: LoRA fine-tuning ($r=16$, $\alpha=32$), learning rate $3 \times 10^{-4}$, 15 epochs.
\end{itemize}

Each model is trained in two conditions:
\begin{enumerate}
    \item \textbf{Baseline}: No temporal information. Input is context + query only.
    \item \textbf{Text time}: Natural-language elapsed time embedded in the prompt (e.g., ``Time since last information: 3 hours ago'').
\end{enumerate}

We also evaluate two additional GPT-2 variants --- \textbf{time tokens} (special tokens like \texttt{<dt\_1h>}) and \textbf{time + memory} (tokens plus memory-age metadata) --- to compare time representations.

Three findings emerge:

\paragraph{1.\ Baselines have zero temporal sensitivity.}
Both GPT-2 and TinyLlama baselines exhibit exactly 0\% switch sensitivity.
Without elapsed-time information, models learn a fixed policy that never adapts to temporal context.
The GPT-2 baseline trusts stale information 32.4\% of the time; TinyLlama is worse at 46.7\%.

\paragraph{2.\ Time annotations create temporal sensitivity.}
All time-aware variants achieve 66--72\% switch sensitivity, correctly changing their action for the majority of counterfactual pairs.
False trust drops from 32--47\% to 0.4--10\%.
The improvement is consistent across model sizes and time representations.

\paragraph{3.\ The shuffled-time ablation confirms causality.}
When elapsed times are randomized across examples --- preserving the distribution of times but breaking the correlation with correct actions --- accuracy drops by 21--30 points.
This proves models are using the temporal signal to make decisions, not exploiting surface-level correlations in the prompt structure.

\subsection{Ablations}

\paragraph{Text time is sufficient.}
Natural-language time (``3 hours ago'') performs comparably to special tokens, and requires no tokenizer modifications.
This is practically important: any system can add elapsed-time annotations as a prompt-layer change.

\paragraph{Paraphrase robustness.}
When time expressions are paraphrased (e.g., ``3 hours ago'' $\to$ ``180 minutes ago''), accuracy drops by 7--17 points but the model retains most temporal reasoning, suggesting partial generalization beyond memorized templates.

\paragraph{Volatility interaction.}
Models show larger accuracy gains on high-volatility facts (flight status, stock prices) than low-volatility facts (birthdays, addresses), confirming they learn the interaction between elapsed time and fact stability.

\section{Experiment 2: Frontier Models}
\label{sec:frontier}

\subsection{Motivation}

The fine-tuning results establish that small models cannot detect staleness without time annotations.
But do frontier models --- trained on orders of magnitude more data, with vastly more parameters --- already handle this?
If even GPT-5.4 and Claude Opus fail without annotations, the temporal blind spot is fundamental, not a capacity limitation.

\subsection{Setup}

We evaluate seven models spanning three providers:
\begin{itemize}
    \item \textbf{OpenAI}: GPT-4o, GPT-4o-mini, GPT-5.4
    \item \textbf{Anthropic}: Claude Sonnet 4, Claude Haiku 4.5, Claude Opus 4.6
    \item \textbf{Local}: Mistral-7B-Instruct-v0.2
\end{itemize}

Each model is tested on 20 hand-crafted scenarios across four conditions:
\begin{enumerate}
    \item \textbf{No time}: No temporal information.
    \item \textbf{Implicit}: Time mentioned casually (``observed 3 hours ago'').
    \item \textbf{Explicit}: Clear annotation: ``Time since this information was observed: 3 hours ago''.
    \item \textbf{Prompted}: Explicit time + system prompt about staleness awareness.
\end{enumerate}

Each scenario is tested in both fresh and stale versions, creating counterfactual pairs.
All calls use temperature 0 for reproducibility.

\subsection{Key Findings}

\paragraph{1.\ The temporal blind spot is universal.}
In the no-time condition, \emph{every model} exhibits near-zero switch sensitivity (0--8\%).
GPT-5.4 --- the most capable model available --- shows 7.7\%, barely above chance.
GPT-4o-mini and Mistral-7B achieve 100\% false trust: they \emph{always} tell users to trust stale information.
This is not a capacity issue.
It is a representation issue.

\paragraph{2.\ Explicit annotations eliminate the blind spot.}
With explicit time annotations, GPT-4o jumps from 7.7\% to \textbf{100\%} switch sensitivity.
Claude Opus jumps from 0\% to \textbf{100\%}.
GPT-5.4 reaches 84.6\%.
False trust drops to 0\% for all three.
The temporal reasoning capability exists in these models --- it simply requires the right input representation to activate.

\paragraph{3.\ Implicit timestamps are insufficient.}
Casually mentioning elapsed time (``observed 3 hours ago'' in a context header) yields only partial improvement: GPT-4o reaches 30.8\% switch sensitivity with implicit time vs.\ 100\% with explicit.
The temporal signal must be \emph{salient} --- clearly labeled and separated from the content --- to be effective.

\paragraph{4.\ Prompting about staleness is the wrong fix.}
The prompted condition adds a system-level instruction to ``consider whether information might be outdated.''
For Claude models, this \emph{hurts}: Claude Sonnet's unnecessary refresh rate rises from 14.3\% to 33.3\%, and Claude Haiku refreshes stable facts 52.4\% of the time.
The time annotation itself, not meta-instructions about staleness, is the active ingredient.

\paragraph{5.\ Smaller models over-correct.}
Claude Haiku and Mistral-7B, upon receiving time annotations, begin refreshing \emph{everything} --- including stable facts like birthdays and capital cities.
Haiku's overall accuracy actually \emph{decreases} in the prompted condition despite eliminating false trust, because it trades false trust for excessive caution.
This reveals a staleness-caution tradeoff that only the most capable models navigate well.

\section{Discussion}
\label{sec:discussion}

\paragraph{Why does this blind spot exist?}
Language model training data contains abundant timestamps, but they appear as \emph{facts about events} (``The meeting is at 3 PM''), not as \emph{signals about context reliability} (``This information is 4 hours old and may be wrong'').
Models learn to process temporal expressions syntactically but not to use elapsed time as a decision-making signal.
The no-time $\to$ explicit gap demonstrates that the reasoning capability exists latently but requires a representation shift to activate.

\paragraph{Implications for deployed systems.}
Every RAG system, tool-using agent, and caching layer that serves previously-observed information to a language model is affected.
Our results suggest three concrete interventions:
\begin{enumerate}
    \item \textbf{RAG pipelines} should annotate retrieved passages with ``Retrieved: [time] ago.''
    \item \textbf{Tool-using agents} should tag tool outputs with ``Observed: [time] ago.''
    \item \textbf{Context caches} should include elapsed-time metadata in the prompt, not just in system logs.
\end{enumerate}
These are trivial engineering changes.
The cost is one additional line in the prompt template.
The benefit, as our results show, is the difference between 0\% and 66--100\% temporal sensitivity.

\paragraph{The staleness-caution tradeoff.}
Time annotations create a new failure mode: over-refreshing stable facts.
Claude Haiku refreshes birthdays and capital cities 52.4\% of the time in the prompted condition.
This suggests that time-aware systems need calibration not just for staleness detection but for \emph{stability recognition} --- understanding that some facts do not go stale.
Fine-tuned models handle this naturally (1--5\% unnecessary refresh) because they learn the volatility--time interaction from training data.
For frontier models, explicit annotation alone is sufficient for the most capable systems (GPT-4o, Claude Opus) but insufficient for smaller ones.

\paragraph{Limitations.}
Our fine-tuning experiments use synthetic data, which limits ecological validity.
The frontier evaluation uses 20 hand-crafted scenarios; larger-scale evaluation would increase statistical power.
We evaluate single-turn decisions; multi-turn temporal reasoning (e.g., tracking staleness across a conversation) remains untested.
We do not evaluate the downstream impact on task completion --- only on action selection.
Finally, our counterfactual design controls for text, tools, and deadlines but not for all possible confounds in the prompt structure.

\section{Conclusion}

Language models at every scale --- from 124M parameters to frontier --- cannot distinguish fresh context from stale context without explicit elapsed-time annotations, exhibiting 0\% sensitivity to elapsed time across all ten models tested.
Adding a single natural-language annotation of how long ago information was observed causes temporal sensitivity to emerge (66--100\%) and dramatically reduces false trust in stale information.
This is likely a blind spot in every agent system that serves cached context without age metadata, and the fix is a trivial change at the prompt layer.

The shuffled-time ablation confirms this is a causal effect: randomizing elapsed times while preserving all other input features drops accuracy by 20--30 points.
Models learn to use elapsed time as a decision signal, not merely to exploit correlations in prompt structure.

We believe this finding has immediate practical consequences.
Any system that presents cached, retrieved, or previously-observed information to a language model should annotate it with elapsed time.
The intervention is lightweight, requires no model retraining for frontier systems, and eliminates a class of failures --- false trust in stale information --- that is otherwise invisible and universal.
